# Cron

Cron schedules are for "run this workflow every X".

## Create a Cron Schedule

Use `Endurant.cron/3` or `Endurant.cron/4`.

```elixir
{:ok, cron} =
  Endurant.cron(
    MyApp.Workflows.BillingSweepWorkflow,
    %{"tenant_id" => "t-1"},
    "0 */5 * * * *"
  )
```

To target a named instance:

```elixir
{:ok, cron} =
  Endurant.cron(
    MyApp.Workflows.BillingSweepWorkflow,
    %{"tenant_id" => "t-1"},
    "0 */5 * * * *",
    instance: :my_endurant,
    name: "billing_sweep_t1",
    timezone: "Europe/Berlin"
  )
```

Options:

- `:id` explicit cron id (UUID string)
- `:name` optional unique cron name
- `:timezone` IANA timezone (`"Etc/UTC"` default)
- `:start_at` start boundary as UTC `DateTime` (`DateTime.utc_now/0` default)
- `:end_at` optional end boundary as UTC `DateTime`

Returns errors such as:

- `{:error, :id_conflict}`
- `{:error, :name_conflict}`
- `{:error, :invalid_cron_expression}`
- `{:error, :invalid_timezone}`
- `{:error, :invalid_window}`
- `{:error, :outside_window}`

## List Cron Schedules

Use `Endurant.crons/0` or `Endurant.crons/1`.

```elixir
all = Endurant.crons()
active = Endurant.crons(status: :active, limit: 100)
paused = Endurant.crons(status: :paused, instance: :my_endurant)
```

Filters:

- `:status` `:active | :paused`
- `:limit` positive integer (default `100`)

## List Cron Fires

Use `Endurant.cron_fires/1` or `Endurant.cron_fires/2`.

```elixir
fires = Endurant.cron_fires(cron.id, limit: 20)
instance_fires = Endurant.cron_fires(cron.id, limit: 20, instance: :my_endurant)
```

Fire rows are the scheduled rows generated by cron dispatch.

Filters:

- `:limit` positive integer (default `100`)

Fire status values:

- `:pending`
- `:dispatched`
- `:skipped`
- `:failed`
- `:cancelled`

## Pause, Resume, Cancel

Pause:

```elixir
:ok = Endurant.pause_cron(cron.id)
```

Resume:

```elixir
:ok = Endurant.resume_cron(cron.id)
```

Cancel:

```elixir
:ok = Endurant.delete_cron(cron.id)
```

Notes:

- Cron row status is user-controlled (`:active` or `:paused`).
- `Endurant.delete_cron/..` deletes the cron schedule row.
- Existing generated fire rows are not deleted by `delete_cron`.

## Config-Managed Crons at Startup

You can define cron schedules in `Endurant.start_link/1` via `:crons`.

```elixir
{:ok, _pid} =
  Endurant.start_link(
    name: :my_endurant,
    repo: MyApp.Repo,
    prefix: "public",
    queues: [default: [concurrency: 10]],
    crons: [
      [
        name: "daily_cleanup",
        workflow: MyApp.Workflows.CleanupWorkflow,
        expr: "0 0 2 * * *",
        input: %{},
        timezone: "Etc/UTC",
        status: :active
      ]
    ]
  )
```

Config cron semantics:

- Names must be unique in config.
- On startup, config crons are upserted by `name`.
- Upsert overwrites schedule fields.
- Startup sync does not delete non-config cron rows.
